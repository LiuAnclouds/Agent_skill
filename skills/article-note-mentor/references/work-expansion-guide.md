# Work 扩写指南

`Work` 是整篇笔记的主体、核心和灵魂。

## 总原则

- 其他部分都服务于 `Work`
- `Work` 默认占正文主体
- 能在 `Work` 里讲清楚的内容，不要扔到边角里

这里锁定五个关键词：

- 深化的
- 紧凑的
- 垂直的
- 充实的
- 证据链闭合的

这几个词不是风格偏好，而是执行约束。所谓“深化的”，是指每个模块都要回答它解决什么问题、依赖什么前提、被什么证据支撑；所谓“紧凑的”，是尽量把同一条逻辑链压在一段厚块中，不让信息被大量小标题打散；所谓“垂直的”，是遇到公式、协议、结果时往下讲清楚，而不是横向扩成很多泛泛话题；所谓“充实的”，是表格后必须有分析、公式后必须有解释、离散结论必须回钩方法和实验；所谓“证据链闭合的”，是任何主要判断都能在主结果、补充分析、附录补证之间找到归宿。最常见的失败形态是：前面讲了很多点，最后却找不到哪张表、哪个消融、哪个实验协议在支撑这些判断。只要存在这种断裂，就说明 `Work` 还没有写够。

## 写法要求

### 1. 顺着论文本身推进

优先遵循论文的原始叙事顺序与论证结构，不要为了套模板而打断论文自身逻辑。但顺着论文推进不等于被论文牵着走；如果原文把关键解释分散在多处，笔记需要主动把它们压回同一解释链。

### 2. 每个模块都要显著增厚

对于 `规则 / 方法论创新 / 实验设计 / 主结果 / 补充分析` 中实际出现的模块，默认要问：

- 这里还有没有可以补的定义
- 这里还有没有可以补的公式解释
- 这里还有没有可以补的上下文关系
- 这里还有没有可以补的证据含义
- 这里还有没有需要提醒的边界或反例

### 3. 统一按闭环推进

每个模块默认顺着下面的链条推进：

1. 定义
2. 机制或公式
3. 作用
4. 证据
5. 边界

不要把其中任何一环长期悬空。尤其不能只写“机制”和“结果”，却不讲二者如何相连。

### 4. 公式要形成逻辑链

不要只把公式抄上来。优先写清：

- 公式是什么
- 符号是什么
- 公式在做什么
- 为什么这样写
- 它在全文方法里负责什么
- 后面哪组实验或结果在支撑它

### 5. 结果要形成证据链

不要只报数。优先写清：

- 这张表里最重要的信号是什么
- 这个信号支持了什么判断
- 它的边界在哪里
- 哪些对比最值得被格式评论阶段显化

### 6. 避免碎片化

如果一段内容仍然在讲同一条逻辑链：

- 用短段
- 用平级分点
- 用表格压重复
- 不要继续新开标题

优先把离散知识压回厚段，而不是拆出越来越多的小节。

## 推荐状态

一篇写得好的 `Work`，读下来应该至少同时满足：

- 顺
- 厚
- 紧
- 可被格式评论阶段准确标出重点
