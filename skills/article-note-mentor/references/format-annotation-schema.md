# 格式标注表结构

格式评论阶段固定输出两份文件：

- `<note>.format-annotations.md`
- `<note>.format-annotations.json`

两份文件的每一条记录必须使用同一组字段：

| 字段 | 含义 | 约束 |
| --- | --- | --- |
| 位置 | 记录正文中的定位信息 | 推荐写成 `章节 > 小节 > 行号` 或 `标题 + 行号` |
| 原文片段 | 被标注的原文片段 | 应足以在飞书块树中定位，不应长到整段失控 |
| 建议动作 | 本条的格式动作 | 只允许 `bold / italic / inline_code / bullet_list / numbered_list / quote_block / table_candidate / highlight_color / tighten_spacing / preserve_spacing` |
| 强度等级 | 动作强弱 | 推荐使用 `high / medium / low` |
| 作用说明 | 为什么要这样处理 | 必须说明它改善的是层级、节奏、强调还是表格化 |
| Feishu 落地样式 | 最终在飞书里的目标样式 | 例如 `文本粗体`、`受控标签色`、`真实表格`、`保留公式前后留白` |

## JSON 约定

JSON 顶层固定为数组；每个对象只包含上述六个字段，不额外夹带实现细节。若需要实现层辅助信息，应在脚本内动态推导，不写回归档文件。

## Markdown 约定

Markdown 固定写成六列表格，表头与 JSON 字段完全同名，便于人工审查和直接 diff。

## 记录粒度

- 一条记录只表达一个主要动作
- 同一句如果既需要加粗又需要颜色，应拆成两条
- 表格候选以整个表格块或连续管道表格为粒度
- 留白类动作以“位置”定位，不要求正文片段很长

## 质量要求

- 每条记录都要能回答“为什么这里值得动”
- 同一位置不应堆叠一串冗余动作
- 记录应能被 Feishu 终稿脚本重复消费，并保持尽量幂等
