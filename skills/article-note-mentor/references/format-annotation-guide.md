# 格式评论指南

这个文件定义格式评论阶段如何从稳定正文中抽取格式决策。

## 总目标

格式评论不是重新写内容，而是回答“这篇已经写好的笔记，哪些地方需要被读者更快看到、哪些地方应该被压平、哪些表述应该被收束”。输出必须可审查、可回退、可被 Feishu 终稿脚本消费。

## 基本判断逻辑

- `bold`：用于核心判断句、转折后的最终结论、表格后明确的读法、带有“这说明 / 更准确地说 / 真正关键是”之类收束功能的句子
- `italic`：用于英文术语、轻量强调概念、需要和周围叙述区分但又不应重压的关键词
- `inline_code`：用于模型名、模块名、字段名、符号名、命令名、公式中反复出现的记号
- `bullet_list`：用于平级结论、平级观察、并列特征，不要求步骤顺序
- `numbered_list`：用于步骤链、闭环链、执行顺序、因果推进顺序
- `quote_block`：用于全文或章节收束句、重要判断、压缩版观点
- `table_candidate`：用于 Markdown 管道表格或明显适合表格呈现的高重复对比
- `highlight_color`：只用于标签、节内小结、关键警示，不应用于整段刷色
- `tighten_spacing`：用于纯空文本块、明显多余空行、打断阅读节奏的冗余留白
- `preserve_spacing`：用于标题前后、公式前后、真实表格前后、引用块周边等必须保留的停顿

## 反模式

- 看见重点词就机械加粗，导致整篇没有层级
- 把所有英文术语都斜体，导致正文像术语列表
- 只标词，不标承担真正阅读转折的句子
- 为了“好看”乱加颜色
- 把本应改成表格的对比信息继续堆成长段

## 与 `Work` 的关系

`Work` 是格式评论的主战场。越是规则密集、结果密集、表格密集、公式密集的区域，越需要格式标注帮助读者抓住主链。判断一个位置是否值得标注时，优先看它是否承担以下功能：

- 引出模块核心定义
- 解释某个公式真正做了什么
- 在表格后给出关键读法
- 对消融或附录补证做收束
- 暴露结论边界

如果一段内容已经写得很厚，但读者仍然难以一眼看出“这里最关键的是哪一句”，就说明这里还需要格式评论。
