# 深化工作流

这个文件定义 `article-note-mentor` 的固定执行顺序。

## 总流程

1. 论文读取与结构定稿
2. 内容写作与分模块深化
3. 格式评论阶段
4. Feishu 原位终稿阶段
5. Markdown 留存归档

## 1. 论文读取与结构定稿

优先收集：

- 标题、作者、机构、会议信息
- 论文主线和核心问题
- 主要公式
- 主要表格
- 附录中真正支撑正文结论的内容
- 现有 Markdown 和飞书文档中已经可保留的结构

先定五个顶层标题：

- `一、前言`
- `二、前备知识`
- `三、Question&Study`
- `四、Work`
- `五、Conclusion`

再固定 `Work` 的五个功能块：

- `规则`
- `方法论创新`
- `实验设计`
- `主结果`
- `补充分析`

## 2. 内容写作与分模块深化

先搭骨架，再逐块加厚。每次只集中解决一个模块，默认追问：

- 这里还缺哪一个定义、变量、公式解释
- 这里与前备知识、问题链和后文证据的关系是否可见
- 这里是否已经形成“机制 -> 作用 -> 证据 -> 边界”的闭环
- 这里是否还存在可解释却被略写的内容

深化结束后统一执行：

- 合并重复定义
- 压缩相邻同义段落
- 删除只承载两三句的微标题
- 把零散解释并回主题块

## 3. 格式评论阶段

写作完成后，不直接进入飞书，而是先生成内部格式标注表。这里要明确找出：

- 哪些句子要粗体
- 哪些概念要斜体或行内代码
- 哪些位置更适合普通分点
- 哪些步骤链更适合编号分点
- 哪些管道表格值得转成真实表格
- 哪些位置需要颜色强调
- 哪些空行应收缩
- 哪些留白必须保留

这一步的目标不是装饰，而是为飞书落地准备一层可审查、可追溯、可重复消费的结构化决策。

## 4. Feishu 原位终稿阶段

固定顺序：

1. 读取飞书块树
2. 结合格式标注表生成 preview 报告
3. 确认修改只停留在样式层和安全清理层
4. 生成本地 backup
5. 原位 apply
6. 回看文档是否接近幂等

终稿阶段只做：

- 强调、列表、引用、颜色、公式和留白节奏的落地
- 保守删除纯空文本块
- 保留真实表格，重建残余管道表格

不做：

- 改论文事实
- 改主线顺序
- 重写方法正文

## 5. Markdown 留存归档

最终保留：

- 主 Markdown
- `.format-annotations.md`
- `.format-annotations.json`
- preview/apply 报告
- 飞书 backup

这些文件共同构成回退层、审查层和后续微调层。
