# 论文笔记模板

当需要新建一篇论文笔记，或对旧笔记做大幅重构时，默认使用这个模板。

## 默认顶层结构

```md
# [论文标题 / 论文深度笔记]

## 一、前言

## 二、前备知识

## 三、Question&Study

## 四、Work

## 五、Conclusion
```

## 标题规则

- 顶层固定为中文序号
- 次级固定为 `1. / 2. / 3.`
- 再次级只在必要时使用 `1.1 / 1.2 / 1.3`
- 标题要凝练，避免把一整段结论写进标题
- 标题既不能太口语，也不能太官样

## 各部分默认任务

### 一、前言

建议包含：

- 论文标题
- 作者与机构
- 会议 / arXiv / 本地文件
- 代码地址
- 一句话核心判断
- 论文定位
- 阅读主线

### 二、前备知识

目标是补齐论文默认你会、但实际上必须讲清楚的知识，而且这些知识必须直接为 `Work` 服务。这里不能只列定义或摘抄背景，而要把“读到正文时会卡住的前提”提前写透。每个知识块默认至少写到：定义、原理或关键公式、变量解释、直观含义、在本文中的具体作用、如果缺这块会在哪个 `Work` 模块掉链子。这里最常见的失败形态是只讲原理不回钩论文、只给术语不给变量、因为怕长而把论文默认前提跳过去。前备知识与正文的衔接必须显式可见：读完这一段后，读者应该知道它会被用在哪个规则、方法、实验或结果分析里。如果某个知识点仍然说不清“它在本文里究竟做什么”，就说明这里还可以继续解释，不应提前收笔。

### 三、Question&Study

目标是把问题链写清楚。

建议包含：

- 研究背景
- 比较缺口
- 核心问题
- 方法主张
- 创新性质
- 证据边界

### 四、Work

这是主体部分。

默认要求：

- 必须是全文最长部分
- 必须是解释最密、逻辑最强的部分
- 必须按论文原始讲解顺序和论证链组织

常见展开顺序：

1. `规则`
2. `方法论创新`
3. `实验设计`
4. `主结果`
5. `补充分析`

但这不是硬模板。若论文自身顺序不同，应以论文为准。

#### Work 写法要求

`Work` 不是“大标题下面堆几句摘要”，而是要把论文真正讲厚的地方压进一个紧凑、垂直、证据链闭合的主体层。每个功能块都应顺着“定义 -> 机制或公式 -> 作用 -> 证据 -> 边界”推进，尽量把相关知识收束在同一厚段里，而不是越写越碎。这里必须覆盖公式后的解释、表格后的分析、协议公平性的来源、作者判断能被哪些证据支撑、还有哪些结论仍未被证明。不能犯的典型错误包括：大段复制实验表不分析、把方法创新写成几条空泛卖点、让 `主结果` 只剩报数、把需要说明的上下文丢回前文或附录。`Work` 与前备知识和结论的关系也必须清楚：前备知识是进入它的桥梁，结论是压缩它的判断。如果你还能补出变量释义、实验因果、模块依赖或边界提醒，就说明这里还可以继续加厚。

#### 公式写法闭环

优先遵循：

1. 公式
2. 符号解释
3. 公式在做什么
4. 为什么这样写
5. 在全文中的作用

#### 实验写法闭环

优先遵循：

1. 比较对象
2. 指标意义
3. 结果说明
4. 支持的判断
5. 仍未证明的边界

### 五、Conclusion

目标是形成稳定最终判断，而不是把前文再薄薄复述一遍。这里默认保留五段式收束：核心结论、主要判断、可借鉴点、局限与改进、全文概括。每一段都要从 `Work` 回收信息，不能写成脱离正文的空泛评价。尤其是“主要判断”和“局限与改进”，必须明确说明哪些判断是被主结果、补充分析和附录证据支撑的，哪些地方仍有边界，避免把论文没有证明的部分说成既成事实。常见错误包括：只写一句“方法有效”、把可借鉴点写成空话、把局限写成礼貌性补充。若结论里还说不清论文真正改写了什么认识，或还无法回钩 `Work` 的关键证据链，就说明这一块仍可继续深化。

## 通用写作规则

- 文件使用 `.md`
- 以飞书阅读为优先
- 用 `**加粗**`、`*斜体*`、分点来显化重点，但避免堆砌
- 表格用于承载核心比较
- 公式不要脱离解释单独存在
- 如果一段内容还在讲同一条逻辑链，就不要继续新开标题
- 定稿前默认生成 `.format-annotations.md` 与 `.format-annotations.json`
