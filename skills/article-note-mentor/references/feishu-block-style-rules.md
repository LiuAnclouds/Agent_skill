# Feishu 块样式映射规则

这个文件定义文本语义如何映射到 Feishu 的块级或行内样式。

## 行内强调

- `bold` -> 文本粗体，用于核心判断句、关键转折和结论标签
- `italic` -> 文本斜体，用于英文术语和轻量强调概念
- `inline_code` -> 行内代码样式，用于模型名、模块名、命令名、字段名、符号名
- `highlight_color` -> 受控文本颜色，只给短句、标签和句内关键判断片段上色，不给整段上色

## 颜色语义

- 蓝色：结构标签、Conclusion 标签、标题型标签、轻量定位语
- 黄色：边界、限制、注意事项、反例提醒、方法适用条件
- 红色：关键纠偏判断、核心反转句、强结论句
- 如果 Feishu 背景高亮 API 不稳定，则统一降级为受控文本色，不引入不稳定样式

## 列表与引用

- `bullet_list` -> 优先命中现有 bullet 块；若当前位置仍是 plain text 且内容本身带有分点语义，应替换成真实 bullet block，而不是只保留一个 `•`
- `numbered_list` -> 优先命中现有 ordered 块；若当前位置仍是 plain text 且承担步骤链语义，应替换成真实 ordered block
- `quote_block` -> 优先保留或利用现有 quote / quote container；若当前位置只是普通 text，但语义上是收束句或总括句，应替换成真实 quote block
- 列表和引用都按“位置命中”验收，不接受“文档别处已经有同类样式”这种替代满足

## 表格

- `table_candidate` -> Markdown 管道表格优先重建为真实 Feishu table block
- 若目标位置已存在真实 table block，则默认保留，只允许修整单元格文本或表格属性
- 不允许为了重建表格而先破坏已有真实表格
- 表格重建必须按位置命中。前言的元信息表、前备知识里的概念表、以及 Work 中的结果表，都不能因为“文档里某处已经有表格”就被视为完成

## 公式

- `$$...$$` 与 `\[...\]` 的整块公式应转为 equation element
- 明显段内 `$...$` 允许转为行内 equation element
- 仅处理可稳定识别的公式，不处理模糊的美元符号文本

## 留白

- `tighten_spacing` -> 仅删除纯空文本块、连续空行中的冗余部分
- `preserve_spacing` -> 保留标题、公式、表格、引用前后的必要停顿
- 任何留白调整都不应破坏已有块结构

## 样式强度

- `high`：核心结论、关键判断、章节收束
- `medium`：术语、标签、局部对比点
- `low`：轻量提醒、阅读节奏微调

## 反模式

- 全文大面积刷粗体
- 用颜色替代逻辑组织
- 把文本块强行拆碎，只为多做几个样式动作
- 把列表语义停留在普通 text 块里，只留下 `•` 或 `1.` 的视觉假象
- 让 `table_candidate` 只做识别和记账，却不在目标位置真正重建为原生表格
- 为了清理空白误删真实内容块
