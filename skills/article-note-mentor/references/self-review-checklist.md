# 自我审查清单

在笔记定稿前，逐项检查。

## 结构

- 是否保留五个顶层标题
- 顶层是否使用中文序号
- 次级是否统一为 `1.`
- 再次级是否只在必要时使用 `1.1`
- `Work` 是否保留 `规则 / 方法论创新 / 实验设计 / 主结果 / 补充分析`
- 是否存在大量只承载两三句的小节

## 内容

- `Work` 是否为全文最长部分
- `前备知识` 是否真的服务于 `Work`
- 重要公式是否有符号解释
- 重要表格是否有解释而不是只贴表
- 表格后是否有分析，公式后是否有解释
- 附录关键证据是否已经吸收进正文逻辑链

## 风格

- 是否太 official
- 是否太口语化
- 是否出现重复空话
- 是否出现用类比替代解释的情况
- 标题是否过长、过碎或过空

## 格式评论

- 是否生成 `.format-annotations.md` 与 `.format-annotations.json`
- 两份格式标注是否字段一致
- 是否明确标出粗体、斜体、行内代码、分点、编号、表格候选、颜色和留白
- 是否避免把加粗和颜色泛滥到整篇都是重点
- 是否把关键纠偏句、边界提醒句、Conclusion 收束句真正标成颜色候选，而不是只标前缀标签
- `table_candidate` 是否按位置生成，而不是只在“文档里有表格”时记为完成

## 飞书可读性

- 段落是否过长
- 分点是否扁平
- 粗体是否用在真正重点处
- 表格、公式、引用块前后留白是否合理
- 真实表格是否被保留
- 空文本块是否只做保守收缩
- 仍是 plain text 的分点或引用，是否已经被替换成真实 bullet / ordered / quote block

## 终稿闭环

- 是否已执行 `preview -> apply -> audit -> 安全补打 -> final preview`
- 是否生成 `.feishu-audit.md` 与 `.feishu-audit.json`
- audit 中是否明确区分漏命中、错命中和稳定不可自动修复差异
- `final preview` 是否达到 `candidate_updates = 0`，或只剩明确声明的稳定残差
- backup、preview 报告、apply 结果和 audit 报告是否在同一归档层完整保留

## 最终判断

- 这篇笔记是否真的遍历并解释了论文中足够多的关键内容
- 读者是否能顺着这篇笔记走完整个论文主线
- 是否仍然有“可以解释却被略写”的地方
- Feishu 终稿阶段是否只落样式，不越界改正文事实
